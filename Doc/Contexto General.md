Prompt Maestro: Sistema Agnóstico de Pagos y Liquidación (Web2/Web3)Instrucción para el LLM/Dev:Actúa como un Arquitecto Principal de Software Fintech y Blockchain. Vamos a diseñar y construir paso a paso un procesador de pagos con arquitectura de microservicios en Rust y contratos inteligentes en Solana.Característica Principal: El sistema debe ser mutable e interactivo con múltiples rieles de liquidación (Multi-Rail), permitiendo procesar compras con tarjeta donde el fondo de respaldo y la liquidación final puedan conmutar entre:Banca Tradicional (Fiat/USD/EUR).CEX Custodial (Binance API / Custodial Wallet).Non-Custodial On-Chain (Solana Program / Anchor).Desarrollaremos el proyecto módulo por módulo. No avances al siguiente paso hasta que te dé la confirmación.🧩 FASE 1: Diseño de Dominio y Capa de Abstracción de Rieles (Payment Rails)Objetivo: Diseñar la arquitectura base en Rust definiendo las interfaces/traits que permitan la mutabilidad del proveedor de fondos y liquidación.Patrón de Diseño: Implementar el patrón Strategy en Rust para desacoplar el origen de fondos (FundingSource) del destino/asentamiento (SettlementRail).Entregables requeridos:Definición de Trait en Rust: trait PaymentProcessor y trait LiquidityEngine.Estructuras de datos (structs y enums) para PaymentRequest, CardPayload, FundingType::[TraditionalBank, BinanceCex, SolanaWallet] y TransactionStatus.Lógica de enrutamiento dinámico (Rail Switcher): un motor de decisión que elija el riel según las reglas de negocio (ej. disponible, comisiones, preferencia del usuario).🧩 FASE 2: El Oracle de Autorización Off-Chain (Rust Microservice)Objetivo: Construir el microservicio que simula la red procesadora (Visa/Mastercard) y ejecuta la validación en tiempo real ($1-3$ segundos).Responsabilidades:Validación del número de tarjeta mediante el algoritmo de Luhn y detección de marca (Visa/Mastercard/Amex).Autenticación con clave privada (X-API-KEY) para comunicarse únicamente con el API Gateway.Evaluación de fondos y límites según el riel activo:Si es Tradicional: Evalúa límite estático o saldo bancario ficticio.Si es Binance: Consulta saldo Spot mediante API simulada y calcula el Hold en USDC/USDT con margen de protección (spread buffer).Si es Solana: Consulta el balance de la wallet On-Chain mediante la RPC de Solana.Entregables requeridos:Código funcional del microservicio HTTP en Rust (usando Axum o Actix-Web).Módulo de lógica de validación de tarjetas y cálculo de disponibilidad.🧩 FASE 3: Motor de Liquidación On-Chain (Solana Program con Anchor)Objetivo: Desarrollar el Smart Contract en Solana que actúa como el libro mayor inmutable de asentamiento para cuando el riel seleccionado sea Web3.Responsabilidades:Crear la instrucción process_payment(amount, brand_code, settlement_rail_id).Transferencia atómica de tokens SPL (USDC/SOL) entre la cuenta del pagador/custodia y la del comercio.Emisión del evento PaymentProcessed para auditoría pública sin exponer información sensible (Zero PII).Entregables requeridos:Código en Rust utilizando el framework Anchor.Estructuras de cuentas y validadores de seguridad (#[derive(Accounts)]).Tests de integración en TypeScript/Rust para simular la ejecución de la transacción.🧩 FASE 4: API Gateway y Orquestación (Rust)Objetivo: Construir el backend principal que conecta la petición del cliente con el Oracle y ejecuta la liquidación en el riel adecuado.Flujo del Orquestador:Recibe la petición del checkout: POST /api/v1/checkout.Consulta al Oracle para autorizar el Hold preventivo del saldo.Si es aprobado, ejecuta el Settlement Engine:Si Rail == Solana: Llama al programa de Anchor utilizando solana-client.Si Rail == Binance: Invocación simulada a la API de Binance para debitar el saldo custodial.Si Rail == Banking: Generación de un archivo de compensación simulado (ISO 20022 / ACH).Devuelve la confirmación al cliente con el ID de transacción o Hash de la Blockchain.Entregables requeridos:Servidor Gateway en Rust.Mapeo de errores y respuestas HTTP estructuradas.🧩 FASE 5: Capa de Presentación (React Dashboard & Checkout)Objetivo: Desarrollar la interfaz web interactiva que demuestre la mutabilidad del sistema.Componentes UI:Formulario de Tarjeta: Entrada de datos ficticios de la tarjeta.Selector Mutador de Riel (Rail Selector): Un dropdown/switch donde el usuario o el comercio elige el método de liquidación (Banco Tradicional, Binance Account, Solana Wallet).Visor de Respuesta: Muestra en tiempo real el log de la transacción, indicando si se usó la red bancaria o el Hash de Solana (Tx Signature).Entregables requeridos:Código del frontend en React con Tailwind CSS.Conexión mediante fetch/axios con el Backend API Gateway.
